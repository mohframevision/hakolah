### 🟠 متوسطة

1. **commit للعمل الجاهز غير المحفوظ.** نفّذ:
   ```
   git status --short
   ```
   بمجلد المشروع الجذر ستجد 16 ملفاً معدّلاً (uncommitted) منذ آخر commit بتاريخ الأحد 13 سبتمبر 23:59، من ضمنها: `cf-worker/worker.js`، `src/css/style.css`، `src/js/main.js`، `src/_includes/detail-item.njk`، `src/_data/i18n.js`، وملفات `*.11tydata.js` لعدة أقسام. هذي التعديلات (ضغط صورة، SRI للوحة التحكم، `try/catch` بالـWorker، ميزة "استمع للمقال" قيد التطوير) موجودة فقط على القرص. نفّذ `git add` و`git commit` لكل مجموعة تعديلات مرتبطة منطقياً على حدة (مثلاً: commit منفصل لإصلاحات الأمان/الأداء الجاهزة، وcommit آخر منفصل لميزة "استمع للمقال" الناقصة — لا تخلطهم بنفس commit). **لا تنفّذ `git push` بدون تأكيد صريح من محمد.**

2. **`/subscribe` و`/unsubscribe` بـ`cf-worker/worker.js` بدون حد لعدد الطلبات (rate limiting).** افتح `cf-worker/worker.js`:
   - السطر 123-131: معالج `POST /subscribe` يستدعي `readJson(request)` بالسطر 124 لكن **لا يستدعي `isRateLimited`** قبل الكتابة إلى KV.
   - السطر 132-149: معالج `POST /unsubscribe` نفس الشي — يستدعي `readJson(request)` بالسطر 133 بدون `isRateLimited`.
   - قارن هذا بمعالجي `POST /like` (سطر 150-171) و`POST /unlike` (سطر 172-191) اللذين يستدعيان `if (await isRateLimited(request, env)) return tooManyRequests();` بالسطرين 156 و176 على التوالي.
   - **الإصلاح:** أضف بنفس الشكل (بعد قراءة الـbody مباشرة وقبل أي كتابة لـKV) بمعالجَي `/subscribe` و`/unsubscribe`:
     ```js
     if (await isRateLimited(request, env)) return tooManyRequests();
     ```
   - السبب: التعليق بالسطر 18-22 من نفس الملف يوضّح أن فحص Origin/Referer لا يمنع سكربتاً يزوّر الترويسة يدوياً. بدون حد طلبات، سكربت بسيط يقدر يستهلك حصة الكتابة اليومية المجانية بـCloudflare KV (1000 كتابة/يوم) ويعطّل الاشتراكات والإعجابات الحقيقية لبقية اليوم.

3. **فشل بناء Eleventy محلياً بخطأ `EPERM` عند نسخ `src/admin`.** نفّذ `npx eleventy` بجذر المشروع وستشاهد:
   ```

   ```
   هذا يمنع اكتمال `npm run build` و`npm run check:i18n` بالكامل رغم أن باقي الصفحات (106 ملف) تُكتب بنجاح. هذا خطأ بيئة محلية على جهاز ويندوز (على الأغلب `_site/admin/index.html` مفتوح ببرنامج آخر — محرر، مستكشف الملفات، أو برنامج مزامنة/فحص فيروسات يقفل الملف مؤقتاً) وليس خطأ بالكود نفسه. **الخطوة المطلوبة من محمد مباشرة (ليست شيئاً يُصلح بالكود):** إغلاق أي برنامج قد يكون فاتح `_site/admin/index.html`، أو حذف مجلد `_site` بالكامل يدوياً وإعادة تشغيل `npm run build` من الصفر.

## 2. الملاحظات القانونية

⚠️ *ملخص بحث عام وليس استشارة قانونية رسمية.* يوجد بجذر المشروع ملف بحث قانوني مُعدّ مسبقاً (`ملاحظات-قانونية-بحرين.md`) يغطي هذي النقاط بتفصيل أعمق — لا تكرر البحث من الصفر، ابنِ عليه مباشرة.

1. **🔴 الأهم: قانون الإعلام الإلكتروني رقم (41) لسنة 2025 (نافذ منذ أكتوبر 2025).** يُدخل ترخيصاً لـ"الإعلام الإلكتروني" بفئة مفتوحة تشمل "أية مواقع إعلامية إلكترونية أخرى" بقرار وزاري، بلا استثناء صريح لأدلة المحلات. قسم "أدلة" التحريري بالموقع (مقالات/تحليلات، بعكس دليل المحلات المباشر) هو الأقرب لتعريف القانون. العقوبة غرامة حتى 10,000 دينار. **هذي نقطة لا يحلّها أي تعديل بالكود** — الإجراء الوحيد الموثوق هو اتصال محمد شخصياً بوزارة الإعلام البحرينية (17872555) بسؤال محدد: هل دليل محلات فيه قسم مقالات عامة يحتاج ترخيص إعلام إلكتروني؟ لا تُنشئ أي محتوى قانوني إضافي بهذا الخصوص قبل ورود جواب رسمي.

2. **🟠 السجل التجاري — "سجلي" (Sijilat) هو الحل الجاهز.** دخل الموقع الحالي (AdSense المستقبلي + عمولة كازاسوق) يُصنَّف نشاطاً تجارياً من حيث المبدأ (عقوبة حتى حبس سنة + غرامة حتى 100,000 دينار بدون ترخيص). "سجلي" سجل مبسّط مخصص بالضبط لفرد بحريني بنشاط أونلاين بلا مكتب، ولا يتعارض مع امتلاك مشروع ثانٍ (القيد أُلغي بتحديث سبتمبر 2024). هذي أيضاً خطوة يتخذها محمد مباشرة عبر sijilat.bh، وليست تعديل كود.

3. **🟢 تسجيل PDPL — خطر منخفض حالياً.** بيانات هكوله الوحيدة (endpoint اشتراك إشعارات) لا تستوفي شروط التسجيل الإلزامي أو تعيين DPO (لا معالجة واسعة النطاق ولا بيانات حساسة). **تحسين اختياري بسيط بالكود:** افتح ملف سياسة الخصوصية (ابحث عنه بـ`grep -rln "سياسة الخصوصية\|privacy" src/_includes src/*/*.md 2>/dev/null` أو داخل `src/_data/i18n.js` إذا كانت النصوص هناك) وأضف جملة صريحة تذكر حقوق صاحب البيانات بموجب PDPL: الاطلاع على بياناته، تصحيحها، وطلب حذفها — بالعربي والإنجليزي.

4. **الإفصاح عن رابط كازاسوق بعمولة موجود وواضح بصفحة الترويج نفسها** (`rel="sponsored"` + نص صريح بالعربي والإنجليزي بـ`src/_includes/cazasouq-promo.njk` أو ما يعادله) **لكن غير مذكور بسياسة الخصوصية أو الشروط.** أضف سطراً واحداً بكل من ملف سياسة الخصوصية وملف الشروط يذكر أن الموقع يحتوي روابط تسويق بالعمولة (affiliate) وأن ذلك لا يؤثر على استقلالية التوصيات.

5. **حقوق الصور — لا مشكلة نشطة حالياً.** لا صور بمجلد `src/assets/uploads/` (المجلد الفعلي المنشور بالموقع) تبدو منسوخة بلا إذن. مجلد "صور المحلات" خارج `src` وغير منشور — أبقِ التنبيه فقط: تحقق من مصدر/إذن أي صورة قبل نقلها لمجلد `src/assets/uploads/` مستقبلاً.

## 3. مقترحات التطوير

### أ) واجهة المستخدم وتجربة المستخدم (UI/UX)

> ⚠️ ملاحظة نطاق: هذي المراجعة اعتمدت على قراءة الكود المصدري (CSS/القوالب) وحسابات تباين الألوان الفعلية (WCAG) برمجياً، وليس على تصفح بصري حي للموقع أو Lighthouse (لا يتوفر متصفح Chrome بهذه البيئة السحابية). التوصيات أدناه دقيقة على مستوى الكود، لكن يُنصح بتأكيد بصري إضافي عبر `node scripts/check-ux.js` أو Lighthouse من جهاز محمد مباشرة.

**🔺 أثر عالٍ**

1. **[إمكانية وصول — ثغرة تباين ألوان حقيقية بجديدة]** افتح `src/css/style.css` السطر 1932:
   ```css
   .form-message.success {
     background: rgba(16, 185, 129, 0.12);
     border: 1px solid #10b981;
     color: #10b981;   /* السطر 1932 */
   }
   ```
   لون النص `#10b981` على خلفية بيضاء/فاتحة (`--color-surface: #ffffff`) نسبة تباينه **2.54:1** فقط — أقل بكثير من الحد الأدنى لـWCAG AA (4.5:1 للنص العادي). هذا نص رسالة نجاح فعلية تظهر للمستخدم بعد إرسال نموذج (مثلاً بعد الاشتراك أو إرسال بلاغ) — صعبة القراءة لأصحاب ضعف البصر أو بإضاءة قوية على الجوال.
   **التعديل المطلوب (غيّر السطر 1932 فقط، أبقِ `background` و`border` كما هي):**
   ```css
   color: #047857;
   ```
   هذا يرفع التباين إلى **5.48:1** (يتجاوز 4.5:1 المطلوب) بلا تغيير جوهري بالهوية اللونية (نفس درجة الأخضر، أغمق قليلاً).

2. **[إمكانية وصول — نفس المشكلة، رسالة الخطأ]** بنفس الملف `src/css/style.css` السطر 1938:
   ```css
   .form-message.error {
     background: rgba(239, 68, 68, 0.12);
     border: 1px solid var(--color-danger);
     color: var(--color-danger);   /* السطر 1938 */
   }
   ```
   `var(--color-danger)` يساوي `#ef4444`، ونسبة تباينه على الخلفية الفاتحة **3.76:1** — أيضاً أقل من 4.5:1 المطلوب لنص عادي بحجم 0.9rem (~14.4px، غير عريض). **مهم:** لا تُعدّل متغيّر `--color-danger` نفسه بالسطر 61 من نفس الملف — هذا المتغيّر مستخدم بأماكن أخرى كأيقونات (قلب المفضلة، خط تحت الحروف الخاطئة باختبار الكتابة) حيث التباين المطلوب فقط 3:1 وهو متوفر حالياً. **التعديل المطلوب — استبدل السطر 1938 فقط بقيمة مخصصة لهذي القاعدة تحديداً:**
   ```css
   color: #dc2626;
   ```
   يرفع التباين إلى **4.83:1**.
   بعد التعديلين، نفّذ `npm run build` وتأكد بصرياً من ظهور الرسالتين بوضوح بكل من الوضع الفاتح والداكن (لاحظ: بالوضع الداكن التباين أصلاً كافٍ — 4.53 و6.72 — لا حاجة لتعديل هناك، لأن `.form-message` لا تُعرّف قيماً مختلفة داخل `@media (prefers-color-scheme: dark)` أو `:root[data-theme="dark"]`؛ تأكد من ذلك بالفحص البصري فقط لتفادي أي تفاجؤ).

3. **[محتوى + UX مدمج]** صفحات قسم "المقاهي" (`src/cafes/`) — 17 من 26 مقهى (65%) وصفها شبه فارغ (كلمة أو كلمتين فقط، حسب `node scripts/check-data-quality.js cafes`). هذا أضعف قسم بالموقع من حيث الاكتمال (بقية الأقسام بين 85%-98% اكتمال)، ويعطي انطباعاً أولياً ضعيفاً لأي زائر يفتح صفحة تفاصيل مقهى تحديداً — بطاقة شبه فاضية أسفل الصورة والعنوان. نفّذ `node scripts/check-data-quality.js cafes` للحصول على القائمة الدقيقة بأسماء الملفات الناقصة، واكتب لكل مقهى وصفاً حقيقياً بجملتين على الأقل (الأجواء، نوع القهوة/المنيو، ليش يستاهل الزيارة) بالعربي والإنجليزي معاً.

**🔸 أثر متوسط**

7. **[إمكانية وصول]** تشغيل `node scripts/check-ux.js` يدوياً من جهاز محمد مباشرة (خارج أي جلسة سحابية) للحصول على تقرير فحص وصول (accessibility) كامل يشمل عناصر تفاعلية معقّدة مثل الحاسبة والتجارب التفاعلية بقسم `ai-experiments` — هذي أدوات لم تُفحص بصرياً بهذي المراجعة.
